## Bugs

### JVBUG-01 — inspector panes leak into presentation mode

- [ ] **Open — reproduced live at `16cd2f7`.**

**Live evidence**

- Open Home → Review and then press Present.
- Before Present, `#reviewpane` was visible at 232×535px.
- After Present, `body` no longer had `slide-editing`, but `#reviewpane.hidden`
  remained `false`; the pane measured 232×701px and covered the right-hand
  side of the audience slide.

**Implementation evidence**

- `setUIMode()` in
  `src/junoview/assets/js/deck/55-sections-and-strip.js:1000-1087` hides
  `#selpane`, Notes, Versions and Animations when editing ends.
- It does not close every registered `.selpane`. `#reviewpane`, `#tidypane`,
  `#preflight`, `#stdpane`, `#flippane`, `#provpane`, `#sizepane` and
  `#objhist` are therefore dependent on whichever individual hide call the
  author happened to remember.

**Required change / completion test**

Route the edit→present transition through the central pane owner and close
every inspector before the first audience render. Reset each trigger's pressed
or expanded state. Add a behaviour test that opens every `.selpane` in turn,
enters Present and asserts that no editor pane has a rendered box.

### JVBUG-02 — File menu runs below the viewport

- [ ] **Open — reproduced live at `16cd2f7`.**

**Live evidence at 1280×720**

- `#dc-menu`: top 8px, height 754.5px, bottom 762.5px.
- Computed `max-height` was `none`; computed `overflow-y` was `visible`.
- The final action, Delete presentation, ran from y=724.2 to y=756.8. Only
  its top edge was inside the 720px viewport.

**Implementation evidence**

- `src/junoview/assets/html/deck.html:74-145` places 19 actions and five
  headings inside `#dc-menu`.
- `.dc-menu` at `src/junoview/assets/css/deck.css:834-846` has no height cap or
  vertical scrolling.
- `floatMenu()` at
  `src/junoview/assets/js/deck/45-images.js:609-624` can move a menu upward,
  but it cannot fit a menu whose own height exceeds the viewport.
- T143's note at `TASKS.md:2731-2747` says the menu “fits”; the live 720px
  measurement disproves that claim for a normal laptop-height viewport.

**Required change / completion test**

Give transient menus an available-height cap such as `calc(100vh - 16px)` and
vertical scrolling, then reconsider whether page setup and source refresh
belong under File at all. Test 720px, 600px and browser zoom at 125%; the last
action must be fully visible, keyboard reachable and never hidden under the
viewport edge.

### JVBUG-03 — custom menus escape the one-overlay contract

- [ ] **Open — reproduced live at `16cd2f7`.**

**Live evidence**

- Open Design → Text styles, then File.
- `#dsg-style-menu` and `#dc-menu` were simultaneously visible and both
  triggers reported `aria-expanded="true"`.
- Clicking outside hid both menus, but Text styles still reported
  `aria-expanded="true"` while hidden.

**Implementation evidence**

- The central owner at
  `src/junoview/assets/js/deck/45-images.js:626-673` promises one transient
  menu and resets ARIA on every close.
- Text styles bypasses it at
  `src/junoview/assets/js/deck/20-notes-and-tables.js:585-597`; its outside
  click writes only `menu.hidden=true` and never resets the trigger.
- The app/deck Theme menu is another custom path at
  `src/junoview/assets/js/app.js:2564-2594`: it does not participate in the
  overlay owner, expose expanded state, close on Escape or restore focus.

**Required change / completion test**

Let dynamically rebuilt menus register an adapter with the same owner instead
of implementing a second ownership system. Opening any menu must close the
previous one; selection, outside click and Escape must all reset ARIA; Escape
must restore focus. Test File↔Text styles, File↔Theme and Text styles↔Theme.

### JVBUG-04 — chart input turns missing or invalid data into zero

- [ ] **Open — direct data-model evidence.**

**Implementation evidence**

- `chartParse()` at
  `src/junoview/assets/js/deck/47-charts.js:35-44` applies `Number(v)` and
  returns `0` for anything non-finite.
- `chartFromRows()` repeats the conversion at lines 248-253.
- `Number('')` is also zero, so a blank cell is indistinguishable from a
  measured zero; `N/A`, a typo or infinity also becomes zero.
- The Edit data dialog at lines 305-343 accepts the resulting structure,
  unlinks `a.ref` and saves it, so the semantic corruption reaches refresh
  comparisons and PowerPoint export.

**Required change / completion test**

Represent missing values as `null`/gaps and reject invalid numeric text with a
row-and-column message. A failed Apply must not modify the chart or remove its
source link. Add tests for blank, `N/A`, whitespace, zero, negative numbers,
infinity and unequal series lengths through parse, render, refresh and PPTX
export.

### JVBUG-05 — reduced motion does not cover object entrance effects

- [ ] **Open — direct CSS and render-path evidence.**

**Implementation evidence**

- `src/junoview/assets/css/core.css:1167-1170` disables transitions, not CSS
  animations.
- `src/junoview/assets/css/deck.css:1720-1726` assigns actual keyframe
  animations to `.an-anim-fade`, `.an-anim-rise` and `.an-anim-zoom`.
- The reduced-motion rule near the end of `deck.css` disables only
  `.slide{animation:none}`; it does not target the object classes.
- `renderAnnots()` adds those classes at
  `src/junoview/assets/js/deck/20-notes-and-tables.js:2363-2369` without a
  reduced-motion check.
- `motionOK()` at
  `src/junoview/assets/js/deck/45-images.js:1759-1772` is used for slide
  transitions; its comment incorrectly assumes disabling transitions also
  prevents the entrance keyframes.

**Required change / completion test**

Under `prefers-reduced-motion: reduce`, reveal built objects immediately and
disable every `.an-anim-*` keyframe. Add a matchMedia-controlled browser test
for Fade, Rise and Zoom, including rotated objects and “skip animations”.

### JVBUG-06 — poster flip-book export uses a falsy index sentinel

- [ ] **Open — deterministic source-path defect.**

**Implementation evidence**

- `outputSlides()` at
  `src/junoview/assets/js/deck/55-sections-and-strip.js:1242-1265` expands a
  multi-frame flip book into several `{i, f}` output entries.
- Poster selection then starts with `var k=0` and assigns a match only while
  `!k`.
- For current slide index 0, output entry `j=0` assigns zero, which stays
  falsy; entry `j=1` therefore overwrites it. The poster export selects frame
  2 rather than frame 1.

**Required change / completion test**

Use `findIndex()` or a `-1` sentinel and define whether poster export should
use the visible flip frame (`a.at`) or a documented fixed frame. Add a fixture
with a one-slide poster, a first-slide multi-frame flip and at least three
frames; assert the exported page contains exactly the intended frame.

### JVBUG-07 — delayed welcome tour interrupts navigation

- [ ] **Open — reproduced during first-load audit; source unchanged.**

**Evidence**

- On a fresh origin, a presentation was clicked after content became usable;
  the welcome tour appeared over that transition. Skipping the tour left the
  notebook underneath and the presentation had to be clicked again.
- `maybeAutoTour()` at `src/junoview/assets/js/app.js:2872-2879` marks the tour
  seen and schedules `tourStart()` 700ms later.
- The callback checks only that `#tour` exists. It does not verify that the
  original view is still active or that the user has not navigated or begun
  another interaction.

**Required change / completion test**

Cancel the pending tour after any navigation/primary action, or start it
synchronously before content becomes interactive. Test a click at 0, 500 and
699ms after `sem:activate`; the intended navigation must complete and no late
overlay may steal it.

### JVBUG-08 — mobile Sections disclosure has stale accessibility state

- [ ] **Open — direct mobile branch evidence.**

**Implementation evidence**

- `#menubtn` at `src/junoview/assets/html/page.html:185-187` has neither
  `aria-expanded` nor `aria-controls`.
- Desktop `applyToc()` updates `aria-pressed` at
  `src/junoview/assets/js/app.js:3096-3106`.
- The mobile click branch at lines 3107-3115 toggles `.rail.open` and the
  scrim, then returns without updating any accessibility state.

**Required change / completion test**

Use a disclosure contract (`aria-expanded` plus `aria-controls`) and update it
for button, scrim, navigation and breakpoint-close paths. Add a test with the
mobile media query active.

## Features that are not complete

### JVFEAT-01 — the animation model is too shallow

- [ ] **Open — implemented feature, incomplete model.**

**Evidence**

- An annotation stores only `a.anim={type, order}` at
  `src/junoview/assets/js/deck/45-images.js:988-996`.
- The pane hard-codes None, Appear, Fade, Rise and Zoom at lines 1016-1035.
- Build order is a sequence of click groups at lines 1055-1092.
- “One by one” and “All at once” overwrite the whole slide's build map at
  lines 1145-1168.

The model cannot express duration, delay, start-with-previous,
start-after-previous, per-effect timing, direction/options, emphasis, exit,
motion paths, repeat, trigger objects or a preview range. It also cannot
distinguish a slide transition from object animation in one coherent editor.

**Required change / completion test**

Define a versioned animation record before adding more buttons: effect family,
variant, start rule, duration, delay, repeat and trigger. Build one timeline
with play-from-selection and exact on-slide preview. Specify fallbacks for HTML,
reduced motion and PPTX export, then test serialization, undo/redo, playback,
reordering, grouped objects and export loss reporting.

### JVFEAT-02 — native charts stop at a small v1

- [ ] **Open — deliberate cuts recorded in source and backlog.**

**Evidence**

- `CHART_TYPES` at `src/junoview/assets/js/deck/47-charts.js:30-34` contains
  only bar, line, scatter and pie.
- The file header at lines 18-24 explicitly excludes per-series colour
  editing, an embedded workbook, stacking, 3D and secondary axes.
- `TASKS.md:2238-2242` also records that a chart made from a table annotation

**Required change / completion test**

Prioritise data correctness and useful analytical controls: per-series
formatting, missing-value policy, linked ranges/tables, stacked and combination
charts, secondary axes, titles/labels/axis bounds, error bars and trendlines.
3D is lower value than those. Each supported property needs matching HTML and
PPTX behaviour or an explicit export-loss report.

### JVFEAT-03 — Review is a five-way launcher

Give all check engines a common finding shape: id, severity, scope, slide,

Render one filterable checklist with Fix, Ignore/Suppress and Go to item.
Counts and export must derive from the same data so they cannot disagree.

## Style, layout and interaction

### JVUX-01 — animation has two competing control surfaces

- [ ] **Open — reproduced live.**

The Animate ribbon exposes None, Fade, Rise and Zoom while the Animations pane
repeats those and adds Appear. The ribbon also offers One by one, All at once
and Remove animations; those commands change every object on the slide, but
their visible labels do not say “this slide”. The scope exists only in a
tooltip.

Evidence is in `src/junoview/assets/html/deck.html:803-834` and
`src/junoview/assets/js/deck/45-images.js:1016-1177`. The source comment calls
this “ONE door”, but the effect chooser is visibly duplicated and the option
sets are different.

**Required change / completion test:** make Animations one destination. Put
the full effect/timing workflow in its pane/timeline; keep at most a compact
Preview and current-effect control in the ribbon. Rename global commands to
state their scope, for example “Sequence all items” and “Remove from this
slide”. Test that the same effects and state appear in every ribbon layout.

### JVUX-02 — icon and label rules are still inconsistent

- [ ] **Open — direct markup evidence against `AGENTS.md` UI invariant.**

Text-only primary controls include:

- File and Save: `src/junoview/assets/html/deck.html:74-75,154-155`
- `+ Add slide` and `§ Section`: lines 358-362
- `+ New slide`: lines 1028-1029

Conversely, the advanced Plot types, Code cell types and Output types doors
are icon-only at `src/junoview/assets/html/page.html:37-62`.

**Required change / completion test:** use a semantic icon plus a short,
persistent word for primary commands. Do not “fix” text-only buttons by making
them icon-only. Preserve the single-row compaction rules and test all supported
width rungs for visible labels and unique icons.

### JVUX-03 — File and Save still lack one clear ownership model

- [ ] **Open — T143 deliberately stopped halfway.**

The same top-left cluster contains `#dc-file`, `#dc-save`, caret-only
`#dc-target`, `#deck-status` and a separate `#qat-auto` control
(`deck.html:74-190`). T143 kept these separate at `TASKS.md:2741-2747`. File
still mixes file lifecycle, source refresh, export/share, page setup and
destructive presentation management; the viewport bug in JVBUG-02 is the
mechanical consequence.

**Required change / completion test:** make one save component that reads as
“Save” plus destination/status and exposes autosave as its setting. Split
Sources, Export/Share and Page setup into their natural ribbon destinations;
keep File for new/open/save/history/rename and a clearly separated Manage
area. A first-time user should be able to predict where each action lives
without opening all five headings.

### JVUX-04 — Arrange is a 34-command flat list

- [ ] **Open — direct construction and CSS evidence.**

- `wireFloatDropdown()` receives 34 commands at
  `src/junoview/assets/js/deck/40-captions-and-components.js:1384-1439`:
  alignment, page centring, distribution, gap closing, z-order, flipping,
  rotation, formations, matching, global styling, eyedropper workflows,
  layout matching and selection.
- `.sh-menu.align-menu` at `src/junoview/assets/css/deck.css:1489-1491` fixes
  the width but supplies no height cap or scrolling.
- Bring to front and Send to back are duplicated as always-visible adjacent
  buttons at `deck.html:1133-1138` and as menu rows at lines 1406-1409 of the
  builder source.

**Required change / completion test:** remove adjacent/menu duplication; group
Align, Distribute, Order, Rotate/Flip, Size and Advanced matching into labelled
sections or submenus. Cap the menu to the available viewport and test every
command at 768px and 600px heights.

### JVUX-05 — tab widgets do not support tab keyboard behaviour

- [ ] **Open — direct semantics and event evidence.**

- Ribbon buttons declare `role="tab"` at `deck.html:397-423`, but have no
  roving `tabindex`, `aria-controls` or associated tabpanel.
- The delegated handler at
  `src/junoview/assets/js/deck/05-figures-and-ribbon.js:1187-1205` handles
  click and double-click only.
- Dynamic tabs at
  `src/junoview/assets/js/deck/07-ribbon-layouts.js:258-277` repeat the missing
  relationships.
- Notes tabs at `deck.html:1752-1756` have no tab roles or announced selected
  state; `20-notes-and-tables.js:308-322` only toggles an `.on` class on click.

**Required change / completion test:** implement the APG tab contract—one
`tabindex="0"`, synchronized selection, tabpanel relationships and
Arrow/Home/End navigation—for both widgets and every dynamic ribbon layout.
If Notes is not meant to be a tab widget, present it as ordinary worded view
buttons instead of styling it like one.

### JVUX-06 — visual dialogs are not keyboard modals

- [ ] **Open — direct markup/open-path evidence.**

Apply look, Arrangements, Style sets and Match slides use `role="dialog"` at
`deck.html:2090-2242`, but omit `aria-modal`. Their open paths in
`40-captions-and-components.js:1005-1013,1135-1143,1252-1280,2397-2437`
remove `hidden` without placing focus inside. Escape handlers are attached to
the dialog itself, so they are unreliable until focus happens to enter it.
Background content remains keyboard reachable and close paths do not restore
the exact opener.

**Required change / completion test:** one dialog manager must provide modal
semantics, accessible heading/name, initial focus, background inertness/focus
containment, document-level topmost Escape and exact opener restoration. Test
mouse open then immediate Escape, Shift+Tab boundaries and stacked attempts.

### JVUX-07 — resize accessibility remains incomplete

- [ ] **Open/partly in progress — direct markup and event evidence.**

- Builder resize remains `<div id="dc-resize">` at `deck.html:305-307` and
  only handles `mousedown` at `src/junoview/assets/js/app.js:2648-2672`.
- T155 (`ca59580`) changed the film handle to a focusable `role="separator"`
  with Left/Right keys and added a visible grip. It does not add
  `aria-valuemin`, `aria-valuemax` or `aria-valuenow`, so a screen reader still
  cannot learn the width it is changing; no reset action is supplied.

**Required change / completion test:** bring the builder handle under the same
keyboard-capable component, and complete the film handle with synchronized
minimum, maximum and current values plus a reset gesture. Keep drag support.
Test keyboard-only use, screen-reader state and 200% zoom.

### JVUX-08 — duplicate Layout menus are not actually identical

- [ ] **Open — direct markup comparison.**

The Design menu at `deck.html:518-534` orders Arrangements before Masters and
uses `layouts`, `inherit`, `plus`, `inherit` icons. The Home copy at lines
1057-1073 orders Masters before Arrangements and uses `inherit`, `objects`,
`copy`, `forward`, despite the parity comment immediately above it.

**Required change / completion test:** generate both menus from one descriptor
so label, icon, order, disabled state, tooltip and callback cannot drift. Add a
descriptor/DOM parity test instead of two sets of substring assertions.

### JVUX-09 — Masters hides the current state

- [ ] **Open — previously requested and explicitly deferred.**

The Design control is the generic “Masters” at `deck.html:607-610`. T144 asked
for `Master: <name> ▾`, but `TASKS.md:2749-2762` deliberately kept a static
label because dynamic width would interact with ribbon fitting. A user must
open a panel to discover whether the slide inherits Default, Branded or no
master.

**Required change / completion test:** expose the current master with bounded
geometry—e.g. `Masters · Branded`, a stable-width adjacent chip or an
