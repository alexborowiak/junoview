# Audit findings — 2026-08-26

The evidence behind **TASKS.md group 9**. That group is the queue: one
entry per theme, short enough to read. This file is what each entry is
made of — for every finding, the code it is about, what the second
reader actually read before letting the claim stand, and the fix it
suggested.

**Read the caveats first.** Every line here is a *claim about code*, not
a defect report. Nothing in this file has been driven in a browser
except the two marked FIXED. This repo's suite is substring greps over
the rendered page: it proves wiring exists and nothing about whether it
works, so it cannot settle any of these. Before acting on one, open the
file and read it — and where it is a behaviour rather than a shape,
drive the editor (CLAUDE.md has the recipe).

**How it was produced.** Seven readers, one per group of tasks, each
given the task's own spec from TASKS.md and told to read the code that
implements it. Then a second reader per group whose only job was to
**refute** each finding by opening the file and proving the machinery
was already there. 24 of 84 claims died at that step and are not in this
file. The figures group's refuter hit an API error, so its findings
(T58) never went through that step at all.

Of the findings opened by hand during the pass, three of three held up.
That is the whole basis for trusting the rest, and it is a small sample.

**T39 has no section here.** The ribbon icon sweep was not part of this
audit — it was a separate mechanical pass that asked every one of the
hundred ribbon controls whether it has words and whether it has an icon,
then put the same question to the live DOM. Its evidence is its commit
and `tests/test_icon_contract.py`.
